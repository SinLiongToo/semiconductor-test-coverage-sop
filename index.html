0目的與範圍Purpose & Scope

當同一顆 die 在 WT（CP）與 FT 兩站、甚至在 RT／HT／LT 多個溫度 corner 下被重複測試相同或高度相關的項目時，若能證明「後站不會抓到前站漏抓的 fail」，即可將該測項自後站移除或降頻抽測，達成 Test Time Reduction（TTR）。 When the same die is tested for identical or highly correlated items at both WT (CP) and FT — often across multiple temperature corners (RT/HT/LT) — proving that "the downstream stage never catches a fail the upstream stage missed" lets that test be removed or sampled downstream, achieving Test Time Reduction (TTR).

本文件的目的是把這個判斷「模板化、流程化」，避免僅憑幾百顆樣本「沒看到 fail」就下結論的常見統計誤區。核心主張：只看 Bin（Pass／Fail）層級不夠，必須下探到 Parameter（實際量測值）層級，才能看見「兩站都 Pass，但 margin 正在被吃掉」的隱性風險，也才能用遠小於 Bin-level 所需的樣本數，取得具科學依據的結論。 This document turns that judgment into a repeatable template and process, avoiding the common statistical fallacy of concluding "safe to remove" from a few hundred zero-fail samples. Core argument: Bin-level (Pass/Fail) data alone is not enough — analysis must go down to the Parameter level (actual measured values) to expose the hidden risk of "both stages Pass, but margin is eroding," and to reach a scientifically defensible conclusion with a far smaller sample size than Bin-level analysis requires.

適用範圍Scope

本 SOP 適用於同一顆 die／同一 unit 在不同測試站別（WT↔FT）或同站不同溫度 corner 間，測試邏輯或量測參數具有實質重疊的候選測項評估。不適用於製程站之間（如 WAT／E-test 與 WT）的相關性分析，該類分析目的與統計假設不同，需另訂流程；也不涵蓋封裝可靠度重新驗證本身（如 bump crack、die crack 等機械性根因確認後的驗證方法與判定準則，見 §10）。 This SOP applies to evaluating candidate test items where the same die/unit is tested with substantially overlapping logic or measured parameters across stages (WT↔FT) or across temperature corners at the same stage. It does not apply to correlation analysis between process-control stages (e.g., WAT/E-test and WT) — those have different objectives and statistical assumptions and require a separate procedure; nor does it cover package reliability requalification itself (the verification methods and pass/fail criteria used once a mechanical root cause like a bump crack or die crack is confirmed — see §10).

Both often only surface after reliability stress (temperature cycling, drop test); root-cause investigation and requalification are package reliability engineering's domain, outside this SOP's scope (see §10).

V93000 / SmarTestAdvantest 的 SoC 測試機平台（常稱 93K）與其測試程式軟體；SmarTest 7 以 C++ 撰寫 test method，SmarTest 8 改用 Java 與 Eclipse 開發環境，見 §13.5。Advantest's SoC tester platform (often called the 93K) and its test-program software; SmarTest 7 test methods are written in C++, SmarTest 8 moves to Java and an Eclipse-based environment — see §13.5.
Trim出廠前對電路做的一次性校準（如燒 fuse／寫 OTP 調整 trim code），用以修正製程變異；trim 前與 trim 後同一測項的量測值代表不同的物理狀態。A one-time factory calibration of the circuit (e.g., blowing fuses / writing OTP trim codes) that corrects for process variation; the same item's value before and after trim represents different physical states.

2流程總覽Process Overview

主流程分七個 Phase（Phase 0–6），前一 Phase 的輸出是後一 Phase 的輸入。Phase 0 是不需要（或只需少量）資料就能先判斷的「硬性守則」（規格強制項目、零覆蓋保護、量測系統有效性、數位 fault coverage 與應力條件查證），先擋掉不該評估、或地基本身就有破洞的候選；Phase 3 則是本 SOP 的統計核心，把 Bin-level、Parameter-level 與（適用時的）溫度 Corner 線性驗證拆成並行的證據線。額外的 Phase 7（虛線／Optional）不是循序步驟，而是客訴事件觸發時才啟動的查證程序；紅色虛線回饋迴路則代表 Phase 7 查證後若發現是「原本覆蓋就不夠」而非單純誤移除，整個流程要回到 Phase 0 重新開始，見 §10。§11 的 WT 自適應測試（Adaptive Test）不是新的 Phase，而是 Phase 4「抽測」決策在 WT 依晶圓區域與產品成熟度的精細化執行方式；§12 的片上量測則是另一種 TTR 手段——不移除測項，而是改用晶片自己的量測電路取代外部儀器。 The main process runs across seven phases (Phase 0–6), each phase's output feeding the next. Phase 0 applies hard rules that need little to no data at all (spec-mandated items, the zero-coverage guard, measurement-system validity, digital fault-coverage and stress-condition verification) to screen out candidates that should never be evaluated, or whose foundation already has a hole; Phase 3 is the statistical core, splitting Bin-level, Parameter-level, and (where applicable) temperature-corner linearity validation into parallel lines of evidence. The extra Phase 7 (dashed / Optional) isn't a sequential step — it's a verification procedure that only runs when a customer complaint triggers it; the red dashed feedback loop represents Phase 7 finding that coverage was genuinely insufficient to begin with, not just a wrong removal, sending the whole process back to Phase 0 — see §10. §11's WT Adaptive Test isn't a new phase; it's a finer-grained way of executing Phase 4's "sample" decision at WT, by wafer zone and product maturity. §12's on-chip measurement is yet another TTR lever — rather than removing a test, it replaces the external instrument with the chip's own measurement circuitry.

3Phase 0 — 前置強制檢查Phase 0 — Hard Gates

在投入任何資料分析之前，先用三個不需要統計證據的「硬性守則」篩掉不該評估移除的候選 —— 這些守則不會被任何統計結果推翻，任一項不通過即直接保留。 Before investing in any data analysis, screen out candidates that should never be evaluated for removal using three hard rules that need no statistical evidence at all — no statistical result can override these; failing any one of them means the item is kept, full stop.

3.1 規格／驗證標準強制項目3.1 Spec / Qualification-Mandated Items

先查客戶 datasheet／spec 書、PPAP 承諾項目，或適用的驗證標準（如 AEC-Q100、JEDEC）測項清單 —— 若該測項被這些文件明確、逐項寫死要求執行，則無論 Incremental Catch 或相關性統計結果多乾淨，都不可移除，因為這已經是契約或驗證等級的承諾，不是工程風險判斷可以覆蓋的範圍。 Check the customer datasheet/spec, PPAP commitments, or the applicable qualification standard's test list (e.g., AEC-Q100, JEDEC) first. If the item is explicitly, individually mandated by one of these documents, it cannot be removed no matter how clean the Incremental Catch or correlation statistics look — that is a contractual or qualification-level commitment, outside the scope of an engineering risk judgment.

執行方式How to Check

在 Phase 1 的測試對應矩陣中新增一欄「規格來源」，逐項標註是否對應到客戶 spec 條款編號或標準條文；找不到明確來源時，預設視為「可評估」而非「強制」，但需在決策紀錄中註明查證過程。 Add a "Spec source" column to the Phase 1 test mapping matrix and tag each item against the corresponding customer spec clause or standard section. When no explicit source can be found, default to "evaluable" rather than "mandated," but record the verification steps taken in the decision log.

⚠ 沒寫在 spec 書上，不代表不是 spec 參數⚠ Not in the Spec Sheet Doesn't Mean Not a Spec Parameter

Spec 書只定義「客戶端量得到」的參數（如 pin 腳上的 VOH、IDDQ），但這些參數是由電路內部的某個節點或機制「產生」出來的——兩者之間存在必然的物理／電路關係（例如某內部 bias 電流或 reference 電壓直接決定了外部某個 spec 參數的中心值與變異）。這類內部測項即使從未出現在 spec 書、PPAP 或驗證標準的條文裡，一旦被移除，等同間接拿掉了對客戶 spec 參數的保證。因此判斷「是否強制」時，不能只查「這個測項名稱有沒有出現在 spec 文件裡」，還要往回問一句：這個測項量到的東西，是不是某個 spec 參數背後的物理成因？如果是，就應該比照 §3.1 的強制項目處理，需要電路設計端（而非只有測試工程）一起確認才能核准移除。 The spec sheet only defines parameters the customer can measure (e.g., VOH, IDDQ at a pin), but those parameters are physically produced by some internal circuit node or mechanism — a necessary physical/circuit relationship connects the two (an internal bias current or reference voltage, for instance, may directly set the center value and variation of an external spec parameter). Such internal test items may never appear in the spec sheet, PPAP, or qualification standard's text, yet removing one is effectively removing the guarantee behind a spec'd parameter. So don't just check "does this item's name appear in the spec document" — also ask: is what this item measures the physical cause behind some spec parameter? If so, treat it the same as a §3.1 mandated item, and get sign-off from circuit design (not test engineering alone) before approving its removal.

3.2 零覆蓋守則3.2 Zero-Coverage Guard

Redundancy 分析的前提是移除的必須是重複的覆蓋，而不是唯一的覆蓋。無論統計證據多強，決策都不可以讓任一 spec 參數在整個流程（所有站別 × 所有溫度 corner）中變成完全沒有測試點覆蓋。 Redundancy analysis only makes sense when what's being removed is duplicate coverage, never the only coverage. No matter how strong the statistical evidence, a decision may never leave any spec parameter with zero test coverage across the entire flow (every stage × every temperature corner).

硬性規則Hard Rule

在核准移除前，回頭檢查 Phase 1 測試對應矩陣：此參數在移除後，是否仍有至少一個站別、至少一個溫度 corner 繼續測試？若答案是否，此候選直接不成立，不需要再進行 Phase 3 的統計分析。 Before approving a removal, re-check the Phase 1 test mapping matrix: after removal, does this parameter still have at least one stage, at least one temperature corner, still testing it? If the answer is no, the candidate is invalid outright — no need to proceed to the Phase 3 statistical analysis.

3.3 溫度 Corner 移除與線性假設3.3 Temperature-Corner Removal & the Linearity Assumption

跨站（WT↔FT）冗餬與跨溫度 corner（RT/HT/LT）冗餘是兩個不同的問題，不能互相替代。若候選是「移除某個溫度 corner 的測試」（例如認為 RT 已涵蓋、HT／LT 可省略），必須額外驗證該參數在溫度間的關係，不能只憑「數值看起來隨溫度平滑變化」就假設線性成立 —— 部分電性參數（如漏電流）隨溫度呈指數關係而非線性，兩點內插／外插在這類參數上會嚴重低估風險。這條證據線在 Phase 3（§6.3）中與 Bin-level、Parameter-level 並列，僅在候選涉及溫度 corner 移除時適用。 Cross-stage (WT↔FT) redundancy and cross-temperature-corner (RT/HT/LT) redundancy are two different questions and cannot substitute for each other. If the candidate is "remove testing at one temperature corner" (e.g., assuming RT already covers it, so HT/LT can be skipped), the temperature relationship must be separately validated — never assume linearity just because values "look smooth across temperature." Some electrical parameters (e.g., leakage current) follow an exponential, not linear, relationship with temperature, and two-point interpolation/extrapolation badly underestimates risk for those. This evidence line sits alongside Bin-level and Parameter-level in Phase 3 (§6.3), and applies only when the candidate involves removing a temperature corner.

3.4 量測系統有效性（Contact／Repeatability／儀器極限）3.4 Measurement System Validity (Contact / Repeatability / Instrument Limits)

在信任任何相關係數或 Cpk 之前，必須先確認量測系統本身是有效的 —— 否則相關性可能只是反映「兩站共享同樣的量測雜訊」，或者反過來，真正的實體冗餘被雜訊蓋過而誤判為不相關。三個常見盲點： Before trusting any correlation coefficient or Cpk, first confirm the measurement system itself is valid — otherwise a correlation might just reflect "both stages sharing the same measurement noise," or conversely, real physical redundancy gets buried under noise and wrongly read as unrelated. Three common blind spots:

  • Contact 品質：探針卡／socket 接觸不良（接觸電阻異常、需要 retouch）會在資料中製造假的變異。務必監控 retest rate、contact resistance 等指標，異常批次要先排除或重測，不能直接拿來做冗餘分析。 Contact quality: poor probe-card/socket contact (elevated contact resistance, needing a retouch) manufactures fake variance in the data. Monitor retest rate, contact resistance, and similar indicators; exclude or retest anomalous lots before using them for redundancy analysis.
  • 測試程式 Repeatability：同一顆 die 在同一站、同一條件下重複測試，量測值的變異（Gauge R&R 中的 repeatability 分量）若太大，會直接壓低任何跨站相關係數的上限 —— 這種情況下低 r 不代表「兩站不相關」，可能只是「量測本身不夠穩定」。 Test-program repeatability: retest the same die at the same station under the same conditions — if the measurement variance (the repeatability component of a Gauge R&R study) is too large, it caps how high any cross-stage correlation can possibly read. A low r here doesn't mean "the two stages are unrelated" — it may just mean "the measurement itself isn't stable enough."
  • 測試項特性與儀器極限：部分參數天生量測雜訊大（如極低漏電流量測接近儀器解析度極限），或該儀器的量測範圍／解析度本身就無法穩定分辨 die 間的真實差異 —— 這種情況下，相關性分析的結論本來就不可靠，不該用來支持移除決策。 Test-item characteristics and instrument limits: some parameters are inherently noisy to measure (e.g., ultra-low leakage current near the instrument's resolution floor), or the instrument's range/resolution simply can't reliably distinguish real die-to-die differences. In that case the correlation analysis's conclusion is unreliable to begin with and shouldn't be used to support a removal decision.
Gauge R&R 變異拆解Gauge R&R variance decomposition
\[ \sigma_{\text{total}}^{2} = \sigma_{\text{part}}^{2} + \sigma_{\text{gauge}}^{2}, \qquad \%R\&R = \dfrac{\sigma_{\text{gauge}}}{\sigma_{\text{total}}}\times100\% \]
σ_gauge 包含 repeatability（同人同機重測的變異）與 reproducibility（換探針卡／機台／人員的變異）。業界常見門檻：%R&R < 10% 視為量測系統可接受，10–30% 需視情況謹慎使用，> 30% 視為不可接受 —— 相關性分析前應先確認此測項的量測系統落在可接受範圍。 σ_gauge combines repeatability (variance from retesting with the same setup) and reproducibility (variance across probe cards/testers/operators). Common industry thresholds: %R&R < 10% is acceptable, 10–30% is marginal and needs case-by-case judgment, and > 30% is unacceptable — confirm this item's measurement system falls in an acceptable range before trusting any correlation analysis built on it.
前提不成立時該怎麼做What to Do When This Precondition Fails

應先改善量測系統（如更換探針卡、調整測試條件、提高儀器解析度），而不是急著用「相關性不夠」的結論來保留或移除測項 —— 因為那個結論本身可能只是雜訊，不是物理事實。 Fix the measurement system first (a different probe card, adjusted test conditions, higher-resolution instrumentation) — don't rush to use a "correlation isn't high enough" conclusion to keep or remove a test, because that conclusion might just be noise, not physics.

上面的 %R&R 門檻要「信任」，本身也需要足夠的重複測試次數才能估得準 —— 這裡常用反查 Chi-Square（reverse chi-square）的方法：母體變異 σ² 的信賴區間可以用樣本變異 s²（n 次重複量測算出）與卡方分布連結；要反過來問「要多少次重複量測，才能讓估出來的 σ 夠精準」，就是把這個關係式倒過來解 n。 Trusting the %R&R threshold above requires enough repeat measurements to estimate it precisely in the first place — a common method here is reverse (inverse) chi-square sample sizing: the confidence interval for a population variance σ² connects to the sample variance s² (from n repeat measurements) via the chi-square distribution. Asking "how many repeats do I need for a precise-enough σ estimate" means solving that relationship backward for n.

σ 的信賴區間（卡方分布）Confidence interval for σ (chi-square distribution)
\[ \sqrt{\dfrac{(n-1)s^{2}}{\chi^{2}_{\alpha/2,\,n-1}}} \;\le\; \sigma \;\le\; \sqrt{\dfrac{(n-1)s^{2}}{\chi^{2}_{1-\alpha/2,\,n-1}}} \]
「反查」的做法：先定義可接受的精確度（例如希望有 90% 信心，估出的 s 落在真實 σ 的 ±25% 以內），再從小的 n 開始代入上式檢查，找到第一個滿足精確度需求的 n —— 這正是 Gauge R&R、Cpk 信賴區間等方法回答「重複量測要做幾次」的標準做法，也和 §6.2(d)／§13.3 統計容忍區間的 k-factor 查表背後是同一套數學（k-factor 本身就是從 t 分布與卡方分布組合推導出來的）。實務上多半直接用統計軟體或查表求解，不需要手動反解。 The "reverse" approach: define the acceptable precision first (e.g., 90% confidence that the estimated s falls within ±25% of the true σ), then plug in increasing n until this inequality is satisfied — that's the standard way Gauge R&R studies, Cpk confidence intervals, and similar methods answer "how many repeat measurements do I need?" It shares the same underlying math as the §6.2(d)/§13.3 statistical-tolerance-interval k-factor tables (those k-factors are themselves derived by combining the t-distribution with the chi-square distribution). In practice this is solved with statistical software or lookup tables rather than by hand.

3.5 數位邏輯 Fault Coverage 與應力條件查證3.5 Digital Fault Coverage & Stress Condition Verification

Phase 7 §10 描述的四種客訴情境中，「數位邏輯 fault coverage 不足」與「原始測試內容應力不夠」這兩種，本質上不是「移除了不該移除的測項」，而是從一開始覆蓋規劃就有缺口。與其等客訴發生才在 Phase 7 回頭查，更好的做法是在 Phase 0 先驗證這兩件事：任何 fault coverage 或應力條件未達標的產品／測項，直接排除在本輪 TTR 候選範圍之外，等基礎覆蓋補齊了再重新評估。 Two of the four complaint scenarios in Phase 7 §10 — insufficient digital-logic fault coverage and insufficient stress in the original test content — aren't really cases of "removing something that shouldn't have been removed." They're gaps that existed in the coverage plan from the start. Rather than waiting for a complaint and tracing it back through Phase 7, it's better to verify both of these in Phase 0: any product/test item whose fault coverage or stress conditions fall short of target is excluded from this round's TTR candidacy outright, until the underlying coverage gap is closed.

  • 數位邏輯 Fault Coverage：查該測試程式對應的 ATPG／fault simulation 報告，確認 stuck-at 與 delay／transition fault coverage 是否達到組織內部訂定的目標值。未達標的測項或整個測試程式，代表向量集合本身有漏洞 —— 這類候選直接排除在 TTR 評估之外，先由 DFT／設計驗證團隊補強向量或 fault model，覆蓋率達標後才重新納入候選。 Digital fault coverage: check the ATPG/fault-simulation report for the test program in question, confirming stuck-at and delay/transition fault coverage meet the organization's internal target. An item or an entire program that falls short means the vector set itself has a hole — exclude such candidates from TTR evaluation outright; have the DFT/design-verification team strengthen the vectors or fault model first, and only re-admit the candidate once coverage meets target.
  • 應力條件：檢查目前的電壓／溫度／頻率等應力範圍，是否有文件依據（如可靠度驗證報告、歷史 field return 分析）支持它足以激發已知的 latent defect 機制，而不是憑經驗法則沿用舊的 guardband。若某參數的覆蓋完全仰賴一個從未被驗證過是否足夠的應力條件，在確認應力條件本身站得住腳之前，不應該把它當成「已充分驗證、可以評估移除重複測項」的基礎。 Stress conditions: check whether the current voltage/temperature/frequency stress range has documented backing (a reliability qualification report, historical field-return analysis) confirming it's sufficient to excite known latent-defect mechanisms — not just an old guardband carried forward by convention. If a parameter's coverage relies entirely on a stress condition that's never actually been validated as adequate, don't treat it as a solid enough foundation to start evaluating redundant-test removal until the stress condition itself has been confirmed.
  • 應力參數本身要有 spec 依據，不是工程師憑經驗設的：應力時間（stress duration）、Vmax、Vmin 這些數字本身就該是一項 spec——查證時要確認的是「這些參數有沒有對應到正式的應力／篩選規格文件（如 burn-in spec、voltage stress spec）」，而不是只看數字表面上合不合理。對數位邏輯電路而言，VHV／VLV（高／低電壓應力）的合適範圍往往牽涉電路本身的時序與漏電行為，測試工程不一定有足夠資訊判斷「多高算過應力、多低算沒效果」——這部分務必找設計端（designer）一起確認，不要由測試端單方面設定。 Stress parameters need their own spec, not ad-hoc engineering judgment: stress duration, Vmax, and Vmin should themselves be a spec — verification here means checking whether these parameters trace to a formal stress/screening spec document (e.g., a burn-in spec, a voltage-stress spec), not just whether the numbers look reasonable on their face. For digital logic circuits, the right VHV/VLV (high/low voltage stress) range often depends on the circuit's own timing and leakage behavior — test engineering doesn't always have enough visibility to judge "how high counts as overstress" versus "how low is ineffective." Always confirm this with the designer; don't let test engineering set it unilaterally.
與 Phase 7 的關聯How This Connects to Phase 7

這條守則是 Phase 7 §10 情境 1、2（fault coverage 不足、應力不夠）的主動版本 —— 與其等客訴發生後才在 §10 回頭查證，這裡先把關，降低同樣的缺口日後變成客訴、甚至要走 8D 的機率。這裡的查證不是要做一次完整的可靠度驗證，而是先確認「地基」沒有已知的破洞，才值得投入 Phase 1–6 的冗餘分析 —— Phase 0 沒先把關，後面統計證據做得再嚴謹，也救不回一開始就沒被涵蓋到的失效模式。 This gate is the proactive counterpart to Phase 7 §10's scenarios 1 and 2 (insufficient fault coverage, insufficient stress) — screening for them here, rather than waiting to trace them back through §10 after a complaint, reduces the chance the same gap later surfaces as a complaint or an 8D. This isn't meant to be a full reliability qualification — it's a check that the "foundation" has no known holes before investing in the Phase 1–6 redundancy analysis. If Phase 0 doesn't catch this first, no amount of downstream statistical rigor can recover a failure mode that was never covered to begin with.

常見誤區Common Pitfall

兩測項「名稱相似、spec limit 相同」不代表等效 —— 務必確認量測電路路徑、負載條件、溫度 corner 是否真的一致，否則配對本身就不成立，後面的統計分析會建立在錯誤前提上。 Two items with similar names and identical spec limits are not necessarily equivalent — always confirm the measurement circuit path, load conditions, and temperature corner truly match. Otherwise the pairing itself is invalid and every downstream statistical analysis rests on a false premise.

常見誤區：Stop-on-fail 讓「沒有資料」被誤讀成「沒有 fail」Common Pitfall: Stop-on-Fail Makes "No Data" Look Like "No Fail"

蒐集資料前務必確認測試程式的執行模式：stop-on-fail（一顆 die 一旦在某測項 fail，程式就中止，後面的測項完全不會執行）跟 continue-on-fail（即使前面 fail，後面測項仍照跑並記錄）差異很大——也要留意這是「跨站（WT／FT）」還是「同站內部」的執行模式，視實際測試流程而定。若程式是 stop-on-fail，那些「fail 點之後」的測項對該顆 die 而言根本沒有資料，不是「沒有 fail」，是「壓根沒測到」。把這種資料缺失誤當成「無 fail 證據」放進 Incremental Catch 或相關性分析，會嚴重低估真實的漏測風險。務必：(1) 先確認候選測項配對是否受 stop-on-fail 影響，受影響的話優先取得 continue-on-fail（或 debug／engineering mode）資料再分析；(2) 資料萃取時明確區分「Pass」「Fail」「未執行（No data）」三種狀態，不要把「未執行」當「Pass」處理。 Before collecting data, confirm the test program's execution mode: stop-on-fail (once a die fails one item, the program halts and every later item never runs) versus continue-on-fail (later items still run and get recorded even after an earlier fail) make a big difference — and check whether this applies across stages (WT/FT) or only within a station, depending on the actual flow. Under stop-on-fail, items after the fail point simply have no data for that die — that's not "no fail," it's "never tested." Treating this missing data as "no-fail evidence" in Incremental Catch or correlation analysis badly underestimates the real escape risk. Always: (1) check whether the candidate pair is affected by stop-on-fail, and if so, get continue-on-fail (or debug/engineering-mode) data before analyzing; (2) when extracting data, explicitly distinguish "Pass," "Fail," and "not executed (no data)" — never treat "not executed" as "Pass."

常見誤區：混用 Trim 前後的資料Common Pitfall: Mixing Pre- and Post-Trim Data

部分測項的量測值只有在電路完成 trim／校準之後才有物理意義（如 bandgap trim 後的參考電壓、振盪器 trim 後的頻率）；trim 前與 trim 後的同一個測項，代表完全不同的東西，不能混在一起做相關性或 Cpk 分析。資料收集前必須先確認：這個測項的數值是 trim 前還是 trim 後？跨站比較時，兩邊是否都基於同一個 trim 狀態（同一次 trim、同一組 trim code）？沒先釐清就直接拿來算 r，很容易把「trim 前的雜訊」跟「trim 後的真實表現」混在一起，得出失真甚至方向相反的結論。 Some test items' measured values are only physically meaningful after the circuit has been trimmed/calibrated (e.g., a bandgap's reference voltage after trim, an oscillator's frequency after trim); the same item pre-trim and post-trim represents two completely different things and shouldn't be mixed together for correlation or Cpk analysis. Before collecting data, confirm: is this item's value pre-trim or post-trim? When comparing across stages, are both sides based on the same trim state (the same trim pass, the same trim codes)? Skipping this check and computing r directly is a good way to blend "pre-trim noise" with "post-trim real performance" and get a distorted, sometimes inverted, conclusion.

常見誤區：Trim 相關或整站移除，要在跑統計之前先篩掉Common Pitfall: Screen Out Trim-Related or Whole-Station Candidates Before Running Statistics

若候選測項是trim 相關（本身在驗證 trim 是否成功，或量測值直接受 trim code 影響），或候選是「整個站別」的移除（例如打算整站跳過某個溫度 corner，而非單一測項），在跑 Phase 3 統計分析之前，就要先把這類候選特別標記出來、額外審慎評估 —— 尤其是trim 相關的溫度係數（TC）。原因：trim 通常只在單一溫度（常見是 WT 端的常溫）執行一次，之後所有溫度／站別的表現，都仰賴這次 trim 對溫度係數的補償是否準確；若拿掉了驗證這個 TC 補償的測項，等於拿掉了唯一能發現「trim 補償失準」的機會。而且這不是漸進式風險 —— 一旦 trim 演算法或製程本身出現偏移，可能整批甚至整個 lot 的溫度補償同時失準，造成的 loss 遠比單一測項的移除大得多（呼應 §6.2(g) 提到的製程漂移風險）。因此候選是 trim 相關或整站移除時，不能只靠 Phase 3 的統計證據做決定，必須先由電路／trim 設計端確認移除後是否仍有其他機制能發現 TC 補償失準（見 Phase 0 §3.1 物理關聯 spec 參數、§3.3 溫度 Corner 線性）。 If a candidate item is trim-related (it verifies whether trim succeeded, or its value is directly set by the trim code), or the candidate is removing an entire station (e.g., skipping a whole temperature corner rather than one test item), flag it for extra scrutiny before running the Phase 3 statistical analysis at all — especially trim-related temperature coefficients (TC). The reason: trim is usually performed once, at a single temperature (commonly room temperature at WT), and every subsequent temperature's/stage's behavior depends on that trim's TC compensation being accurate. Removing the item that verifies this TC compensation removes the only chance to catch a compensation failure. And this isn't a gradual risk — if the trim algorithm or the process itself drifts, an entire batch or lot's temperature compensation can fail at once, producing a loss far larger than removing any single test item (echoing the process-drift risk noted in §6.2(g)). So when a candidate is trim-related or involves removing a whole station, Phase 3's statistical evidence alone isn't enough to decide — circuit/trim design must first confirm some other mechanism can still catch a TC compensation failure (see Phase 0 §3.1's physically-linked spec parameter and §3.3's temperature-corner linearity).

6Phase 3 — 統計分析方法Phase 3 — Statistical Analysis Methods

這是整份 SOP 的核心：Bin-level 分析回答「有沒有看到 fail」，Parameter-level 分析回答「margin 有沒有在流失」，溫度 Corner 線性分析回答「未測的溫度點是否仍被可靠預測」。三者互補，而非其中一種可以取代另一種；溫度 Corner 線性分析僅在候選涉及移除溫度 corner 時才需要（見 Phase 0 §3.3）。 This is the core of the SOP: Bin-level analysis answers "did we see a fail?"; Parameter-level analysis answers "is margin eroding?"; temperature-corner linearity analysis answers "is the untested temperature point still reliably predicted?" All three are complementary — none replaces another; the temperature-corner line is only required when the candidate involves removing a temperature corner (see Phase 0 §3.3).

6.1 Bin-level（屬性資料）分析6.1 Bin-Level (Attribute Data) Analysis

對候選 pair 統計 Incremental Catch：WT Pass、FT 該測項 Fail 的顆數。若在觀察樣本中 Incremental Catch = 0，只能說「在這個樣本數下沒觀察到」，還不能說「風險為零」—— 這正是 Bin-level 方法的統計弱點：它是二元資料（attribute data），要把「零事件」轉換成「風險上界」，需要非常大的樣本數。 For each candidate pair, count Incremental Catch: units that Pass at WT but Fail this item at FT. An observed Incremental Catch of 0 only means "not observed at this sample size" — not "zero risk." This is the statistical weakness of Bin-level methods: because the data is binary (attribute data), converting a "zero-event" observation into a risk upper bound requires a very large sample size.

6.2 Parameter-level（變數資料）分析 —— 本 SOP 的重點6.2 Parameter-Level (Variables Data) Analysis — The Focus of This SOP

Bin-level 只看「有沒有跨過 spec limit」，看不到「距離 spec limit 還有多遠、這個距離是不是在縮小」。同樣是「WT、FT 都 Pass」的兩顆 die，一顆 margin 很寬、一顆貼著 FT limit，Bin-level 資料完全無法區分，但這正是後續製程漂移或環境應力（如封裝、burn-in、溫度循環）造成漏測的高風險族群。 Bin-level data only tells you whether a value crossed the spec limit, not how far from the limit it sits or whether that distance is shrinking. Two dies that both "Pass at WT and FT" can be indistinguishable at the Bin level — one with wide margin, one sitting right against the FT limit — yet the latter is exactly the high-risk population most likely to escape after downstream process drift or environmental stress (packaging, burn-in, temperature cycling).

(a) 相關性驗證 — Pearson / Fisher z(a) Correlation Validation — Pearson / Fisher z

對同一 parameter 在 WT、FT 兩站的量測值做相關係數 r 檢定，確認兩站量測確實反映同一物理量，且相關性穩定高於可接受下限 r_min（而非只看單次樣本的 r 剛好夠高）。前提是 Phase 0 §3.4 的量測系統有效性已經確認——量測雜訊過大時，算出來的 r 偏低不代表兩站真的不相關，只代表量測系統蓋過了訊號。 Test the correlation coefficient r between WT and FT measured values for the same parameter, confirming the two stages truly reflect the same physical quantity and that the correlation reliably exceeds an acceptable floor r_min (not just that a single sample's r happens to clear the bar). This assumes Phase 0 §3.4's measurement-system validity has already been confirmed — when measurement noise is too large, a low computed r doesn't mean the two stages are truly unrelated, only that the measurement system is drowning out the signal.

(d) 變數抽樣法所需樣本數遠小於屬性抽樣(d) Variables Sampling Needs Far Fewer Samples Than Attribute Sampling

這是 Parameter-level 分析背後的統計原理：屬性資料（Pass/Fail）每顆只回傳 1 bit 資訊，要把「零事件」轉換成低 DPPM 等級的信心上界，天然需要極大樣本；變數資料（實際量測值）每顆回傳連續資訊（均值與變異數都在估計中被使用），可用統計容忍區間（statistical tolerance interval）方法，以遠小的樣本數（實務上常見 n = 30～200 等級）對母體比例做同等信心水準的宣稱。方法與 k-factor 查表請參考 ASTM E2586 / ISO 16269-6（見附錄）；k-factor 背後「用卡方分布反查所需樣本數」的推導方式，見 §3.4 的反查 Chi-Square 說明。 This is the statistical principle behind Parameter-level analysis: attribute data (Pass/Fail) carries only 1 bit per unit, so converting a zero-event observation into a low-DPPM confidence bound inherently requires a huge sample. Variables data (actual measured values) carries continuous information per unit — both mean and variance are used in the estimate — so a statistical tolerance interval method can make an equivalent-confidence population claim with a far smaller sample (commonly n = 30–200 in practice). See ASTM E2586 / ISO 16269-6 for the method and k-factor tables (Appendix); for how those k-factors trace back to reverse-solving the chi-square relationship for sample size, see §3.4's reverse chi-square note.

(e) 全矩陣相關性 — 同站跨溫度 vs 跨站同溫度(e) Full Correlation Matrix — Same-Stage Cross-Temperature vs. Cross-Stage Same-Temperature

候選配對不該只鎖定「WT vs FT、同一溫度」這一組。同一參數實際上最多有六個量測點（WT-RT／WT-HT／WT-LT／FT-RT／FT-HT／FT-LT），應該用 (a) 的方法對所有存在的配對都算一次相關係數，畫出完整的相關矩陣，原因有二： Candidate pairs shouldn't be limited to "WT vs FT at the same temperature." A given parameter has up to six measurement points (WT-RT/WT-HT/WT-LT/FT-RT/FT-HT/FT-LT); use the method in (a) to compute a correlation coefficient for every pair that actually exists, and build the full correlation matrix. Two reasons:

  1. 同站跨溫度（如 WT-RT 對 WT-HT）本身可能就有很高的相關性 —— 這代表的是「溫度 corner 冗餘」而非「跨站冗餘」。這類配對即使 r 很高，也必須額外通過 §6.3 的線性／TC 模型驗證才能核准移除，因為相關係數高不代表關係是線性的，也不代表兩端物理機制相同。 Same-stage, cross-temperature pairs (e.g., WT-RT vs WT-HT) can themselves be highly correlated — that's temperature-corner redundancy, not cross-stage redundancy. Even with a high r, such pairs must still additionally pass the §6.3 linearity/TC-model validation before removal is approved, since a high correlation coefficient neither implies a linear relationship nor that both ends share the same underlying physics.
  2. 跨站同溫度（如 WT-RT 對 FT-RT）才是 (a)–(d) 處理的標準案例。矩陣中相關性偏低的配對，無論同站跨溫或跨站同溫，都應直接排除移除候選，不需要進到 Phase 4。 Cross-stage, same-temperature pairs (e.g., WT-RT vs FT-RT) are the standard case that (a)–(d) already cover. Any pair in the matrix with low correlation — same-stage or cross-stage — is disqualified as a removal candidate and does not proceed to Phase 4.

(f) Outlier Detection — 個體層級異常偵測(f) Outlier Detection — Individual-Level Anomaly Screening

高相關係數、良好線性都只是「母體層級」的證據，不保證沒有個別 die 是離群值 —— 樣本數一大，少數 outlier 對整體 r 或 R² 的影響會被稀釋，異常反而被平均掉而看不見。核准移除前，應在殘差上額外跑一次個體層級的異常偵測： A high correlation coefficient and good linearity are only population-level evidence — they don't guarantee no individual die is an outlier. As sample size grows, a handful of outliers get diluted in their effect on the overall r or R², averaging the anomaly away until it's invisible. Before approving removal, run an individual-level outlier-detection pass on the residuals:

  • NNR（Nearest Neighbor Residual）：把每顆 die 的量測值與晶圓上鄰近 die 的平滑預測值比較，殘差過大視為空間異常（典型的 Good-Die-in-Bad-Neighborhood 現象），能抓到單靠站間或溫度相關性看不出來的局部異常。 NNR (Nearest Neighbor Residual): compare each die's measured value against a smoothed prediction from its spatial neighbors on the wafer; a large residual flags a spatial anomaly (the classic "Good Die in Bad Neighborhood" pattern) — catching local anomalies that a stage- or temperature-correlation check alone would miss.
  • DPAT（Dynamic Part Average Testing）：不用固定 spec limit，改用每個 lot／wafer 自己的統計分布（mean ± kσ）動態計算限制；即使數值仍在 spec 內，只要明顯偏離同批分布就會被標記。 DPAT (Dynamic Part Average Testing): instead of a fixed spec limit, compute limits dynamically per lot/wafer from that batch's own statistics (mean ± kσ); a die can still be flagged for sitting well outside its own batch's distribution even while inside spec.
  • 雙變量／多變量異常偵測（如 Mahalanobis 距離）：單一參數看起來正常，不代表兩個相關參數的「組合」正常 —— 用 Mahalanobis 距離同時看多個維度，才能抓到只有在聯合分布上才顯形的離群點。 Bivariate/multivariate outlier detection (e.g., Mahalanobis distance): a value can look normal on each parameter individually yet be abnormal in the combination of two correlated parameters — Mahalanobis distance looks across multiple dimensions at once to catch outliers that only show up in the joint distribution.

這條檢查獨立於相關係數與線性驗證：任何一種方法標記出的 outlier 都應該讓該候選回頭複查，而不是被一個看起來很高的整體 r 值掩蓋過去。 This check is independent of the correlation coefficient and linearity validation. Any outlier flagged by any of these methods should send the candidate back for review, rather than being smoothed away by a reassuringly high aggregate r.

各方法的實作細節： Implementation details for each method:

  • Static PAT（SPAT）與 Dynamic PAT（DPAT）：SPAT 用多個歷史 lot 的資料算出固定 limit（robust mean ± 6 robust σ），寫進測試程式；DPAT 在每個 lot／wafer 測完後，用這批通過 SPAT 的 die 重新算一次 limit，且 DPAT limit 不得比 SPAT 寬。兩者都要用 §6.2(h) 的 robust σ，否則離群值會撐寬自己的 limit。 Static PAT (SPAT) vs. Dynamic PAT (DPAT): SPAT computes fixed limits (robust mean ± 6 robust σ) from several historical lots and writes them into the test program; DPAT recomputes the limits after each lot/wafer is tested, from the die that passed SPAT, and a DPAT limit may never be wider than the SPAT one. Both must use §6.2(h)'s robust σ, or the outliers widen their own limits.
  • NNR 的計算步驟： NNR, step by step:
    1. 定義鄰域：常用 3 × 3（8 顆鄰居）或 5 × 5（24 顆）視窗；只用有效 parametric 值的鄰居（排除 fail、未測、partial die）。有效鄰居少於門檻（如 8 顆中少於 5 顆，示範值）時——常見於邊緣——把視窗放大到 5 × 5，仍不足就不判定，而不是用少數鄰居硬算。 Define the neighborhood: typically a 3 × 3 window (8 neighbors) or 5 × 5 (24); use only neighbors with valid parametric values (exclude fails, untested, and partial die). If valid neighbors fall below a threshold (e.g., fewer than 5 of 8 — an illustrative value), as often happens at the edge, widen to 5 × 5; if still too few, don't judge that die rather than forcing a call from a handful of neighbors.

Count how many fails surround a good die (optionally weighted: adjacent 1, diagonal 1, outer ring 0.5); above a threshold (e.g., ≥ 6 of 8 neighbors failing — illustrative), the die is suspect. The idea is that defects cluster, so a good die in the middle of a fail cluster likely carries a latent defect that hasn't shown up yet.
  • ZPAT（Z-axis PAT）：把同一 lot 所有 wafer 的 bin map 依 X,Y 疊起來（Z 軸方向），若某個座標在多數 wafer 上都 fail，代表系統性問題（如 reticle 缺陷、probe card 某根針），該座標上剩下的 good die 也列為可疑。與 §11.2 的「shot 內位置」分區是同一種思維。 ZPAT (Z-axis PAT): stack the bin maps of every wafer in the lot by X,Y (along the Z axis); if a coordinate fails on most wafers, the cause is systematic (e.g., a reticle defect or one probe-card needle), and the remaining good die at that coordinate are treated as suspect too. It's the same thinking as §11.2's in-shot-position zoning.
  • 迴歸殘差（多變量的簡化版）：用同一顆 die 的其他相關參數預測這個參數（如由 Idsat、Vth 預測 Freq），對殘差做 robust z。比 Mahalanobis 直觀、容易解釋給客戶，也是 §6.2(g) 迴歸模型的延伸。 Regression residual (a simplified multivariate method): predict this parameter from other correlated parameters on the same die (e.g., Freq from Idsat and Vth) and take the robust z of the residual. 雙變量方法的前提Prerequisites for Bivariate Methods

(1) 平均值、σ、ρ 要用 robust 方式估計（如 MCD，Minimum Covariance Determinant），否則離群點會把 ρ 拉低、橢圓撐胖而遮住自己——與 §6.2(h) 的 masking effect 相同。(2) 參數之間要有物理上說得通的相關性，而且 ρ 在各 lot 間穩定；ρ 不穩時橢圓本身就不可靠。(3) 偏斜參數（如 IDDQ 常呈 log-normal）先取 log 再計算。(4) 門檻（本例 1 ppm）與 DPAT 一樣要事先訂定、追蹤 kill rate，不能看完結果再調。 (1) Estimate the means, σ, and ρ robustly (e.g., MCD — Minimum Covariance Determinant); otherwise the outliers drag ρ down and fatten the ellipse until it hides them — the same masking effect as §6.2(h). NNR、DPAT、GDBN、ZPAT 多半是測完後離線計算，結果要透過 map 修改（inkless map）送到封裝端——務必確認修改後的 map 真的被封裝端使用，並在 STDF／map 中保留每顆被判退 die 的原因碼。門檻 k 與鄰域定義要事先訂好並納入版本控管，不能在看到某個 lot 的結果後才調整；若用於車用產品，方法與門檻通常需要客戶同意。 NNR, DPAT, GDBN, and ZPAT are mostly computed offline after testing, and their results reach assembly through a map edit (inkless map) — confirm that assembly actually uses the edited map, and keep a reason code for every rejected die in the STDF/map. For automotive products, the methods and thresholds usually need customer agreement.

(g) 主動收緊前站 Limit（Guardbanding）作為 Enabler(g) Actively Tightening the Upstream Limit as an Enabler

有時候相關性不是天生就「夠高」，但仍然可以透過收緊前站（如 WT）的測試 limit，主動換取移除後站測試的空間。原理：用迴歸模型從前站量測值推算後站預期值，再加上預測區間（prediction interval）的安全緩衝；只要收緊後的前站 limit 距離這個緩衝夠遠，通過收緊後前站測試的 die，其後站預測值就能以目標信心水準保證落在後站 spec 之內。 Sometimes the raw correlation isn't naturally "high enough" on its own, but removal headroom can still be actively created by tightening the upstream (e.g., WT) test limit. The principle: use the regression model to project the expected downstream value from the upstream measurement, then add a safety buffer sized by the prediction interval. As long as the tightened upstream limit sits far enough beyond that buffer, any die passing the tightened upstream test is guaranteed — at the target confidence level — to land inside the downstream spec.

收緊後前站 limit（guardband）Guardbanded upstream limit
\[ L_{\text{upstream}}' = f^{-1}(L_{\text{downstream}}) \mp z \cdot \sigma_{\text{residual}} \]
f⁻¹ 是迴歸模型的反函數（把後站 limit 換算回對應的前站值），z 依目標信心水準選擇（如 99.7% 取 z=3），σ_residual 是迴歸殘差標準差；「∓」的方向依 limit 是上限或下限而定。 f⁻¹ is the inverse of the regression model (mapping the downstream limit back to the corresponding upstream value); z is chosen by the target confidence level (e.g., z=3 for ~99.7%); σ_residual is the regression's residual standard deviation. The sign of "∓" depends on whether the limit is an upper or lower bound.

這個做法不是免費的：收緊 limit 會讓原本在舊 limit 內、新 limit 外的 die 在前站就被判退，即使它們原本在後站測試也會 Pass。決策時必須把「犧牲的前站良率成本」跟「移除後站測試省下的 test time」放在同一個 ROI 天平上比較（見 Phase 4 ROI 參考），而不是只看統計上站不站得住腳。當相關性 r 已經很高、殘差很小時，收緊的幅度通常很小、犧牲的良率可忽略；相關性普通時，才需要認真評估這筆交易划不划算。 This isn't free: tightening the limit means dies that would have passed the old limit but fall outside the new one get rejected upstream — even though they would have passed the downstream test. The decision must weigh "upstream yield sacrificed" against "test time saved by removing the downstream test" on the same ROI scale (see the Phase 4 ROI reference), not just whether the statistics hold up. When r is already high and the residual is small, the required tightening is usually tiny and the sacrificed yield negligible; when correlation is only moderate, this trade-off needs careful evaluation before committing to it.

⚠ 風險：製程漂移會讓 guardband 失效⚠ Risk: Process Drift Can Invalidate the Guardband

收緊後的 limit，是根據「目前」的 Cpk／σ_residual 算出來的 guardband —— 這個假設不是永久成立的。一旦未來製程出現較大變異（Cpk 惡化、分布變寬或偏移），原本算好的緩衝可能不夠，而且因為後站測試已經移除，當下不會有任何機制能抓到這個 escape，等到問題被發現時，往往已經是一批甚至數批的 loss，遠比「多測一個已冗餬的測項」的成本高出許多。因此 §6.2(g) 的收緊 limit 方案，比單純的冗餘移除更依賴製程穩定度：除了大數據歷史分析之外，也必須掌握 PCM／WAT（製程監控／晶圓允收測試）與此參數的相關性，把它當作比 WT/FT 資料更早的製程異常訊號，並列為 Phase 5 SPC 監控清單中的必要項目，而不是選配。 The tightened limit's guardband is sized from the "current" Cpk/σ_residual — that assumption does not hold forever. If the process later shows larger variation (Cpk degrades, the distribution widens or shifts), the buffer sized for the old distribution may no longer be enough — and because the downstream test has already been removed, there is no mechanism left to catch that escape in real time; by the time it's discovered, the loss is often a full lot or several lots deep, far more costly than simply keeping "one already-redundant test." Because of this, the §6.2(g) tightened-limit approach depends on process stability more heavily than plain redundancy removal: beyond historical big-data analysis, also track the correlation between this parameter and PCM/WAT (Process Control Monitor / Wafer Acceptance Test), treat it as an earlier process-shift signal than WT/FT data, and make it a required — not optional — item on the Phase 5 SPC monitoring list.

(h) Robust σ — 什麼時候用、什麼時候不能用(h) Robust σ — When to Use It and When Not To

一般標準差（classical σ）對離群值非常敏感：少數 contact 飛點、混入的子族群或 fail 尾巴，就能把 σ 撐大好幾倍。Robust σ 用中位數與分位數估計「主體分布」的寬度，不受少數離群值影響。兩種常用估計式（在常態分布下都與 σ 一致）： The ordinary standard deviation (classical σ) is very sensitive to outliers: a few contact flyers, a mixed-in sub-population, or a fail tail can inflate σ several times over. Robust σ estimates the width of the main body of the distribution from the median and quantiles, so a handful of outliers barely moves it. Two common estimators (both consistent with σ under a normal distribution):

Robust σ 估計式Robust σ estimators
\[ \hat{\sigma}_{\text{MAD}} = 1.4826 \cdot \operatorname{median}\bigl(|x_i - \tilde{x}|\bigr) \qquad \hat{\sigma}_{\text{IQR}} = \dfrac{Q_3 - Q_1}{1.349} \]
\(\tilde{x}\) 為中位數。AEC-Q001 PAT 用的就是這類 robust 估計：robust mean = 中位數，robust σ = (Q3 − Q1)／1.35，limit = 中位數 ± 6 robust σ。代價是統計效率較低：常態資料下 MAD 與 IQR 的效率都只有約 37%，要達到與 classical σ 同樣的精確度，大約需要 2.7 倍樣本。 \(\tilde{x}\) is the median. AEC-Q001 PAT uses exactly this kind of robust estimate: robust mean = median, robust σ = (Q3 − Q1)/1.35, limits = median ± 6 robust σ. The cost is lower statistical efficiency: on normal data both MAD and IQR are only about 37% efficient, so matching classical σ's precision takes roughly 2.7× the sample.

選用原則：哪一種 σ 對「這個決策」比較保守，就用哪一種。 Selection rule: use whichever σ is more conservative for the decision at hand.

溫度係數（TC）線性模型Temperature-coefficient (TC) linear model
\[ \hat{x}(T) = x(T_{\text{ref}}) + TC \cdot (T - T_{\text{ref}}) \]
先用至少三個溫度點（而非只有兩點內插／外插）對每顆 die 做回歸，檢查殘差是否隨機、R² 是否夠高，藉此驗證線性假設本身是否成立 —— 而不是預設它成立。若參數本質上非線性（例如漏電流通常呈 Arrhenius／指數關係、部分開關特性呈折線而非直線），必須改用該參數對應的物理模型，或直接判定此節不適用、保留該溫度 corner 測試。 Fit a per-die regression using at least three temperature points (never a two-point interpolation/extrapolation), and check whether the residuals look random and R² is high enough — this tests whether the linearity assumption actually holds, rather than presuming it. If the parameter is inherently non-linear (e.g., leakage current typically follows an Arrhenius/exponential relationship; some switching characteristics are piecewise rather than straight-line), use that parameter's proper physical model instead, or simply conclude this section does not apply and keep the corner's test.

線性假設成立後，用該模型從已測 corner 推算未測 corner 的預測區間（prediction interval），確認預測值距離該 corner 的 spec limit 仍有足夠 margin（同 §6.2(b) 的 guardband 概念，只是把「跨站」換成「跨溫度」）；同時比較已測 corner 與（歷史或抽測）未測 corner 的相關係數 r，樣本數估算沿用 §6.2(a) 的 Fisher z 公式。 Once linearity holds, use the model to project a prediction interval from the tested corner(s) to the untested corner, and confirm the projected value still has adequate margin to that corner's spec limit (the same guardband concept as §6.2(b), with "cross-stage" swapped for "cross-temperature"). Also compare the correlation coefficient r between the tested corner and a historical or sampled untested corner; estimate the required sample size with the same Fisher z formula as §6.2(a).

與 FMEA 交叉檢查Cross-Check Against FMEA

If that pushes the RPN (Risk Priority Number) past an acceptable threshold, the removal shouldn't be approved no matter how clean the Phase 3 statistical evidence looks. FMEA and this SOP's risk tiering are complementary, not substitutes: Phase 3–4's statistics answer "is there evidence supporting removal," FMEA answers "how much does removal change the product's overall failure-mode risk" — both need to pass before moving into Phase 5.

即使統計驗證通過，也不建議直接 100% 移除，先以可回退的方式導入： Even after statistical validation passes, avoid an outright 100% removal — roll out in a reversible way first:

  • SPC 監控：對該測項的 margin／Cpk 建立管制圖，設定觸發線；一旦趨勢異常，自動恢復 100% 測試。若該測項是透過 §6.2(g) 收緊前站 limit 才核准移除，PCM／WAT 與此參數的相關性監控為必要項目，不是選配 —— 製程層級的變異通常會先反映在 PCM/WAT，而不是等到 WT/FT 資料才看得出來。 SPC monitoring: Build control charts for the item's margin/Cpk with trigger limits; automatically restore 100% testing if the trend goes out of control.   • 定期重新驗證：製程節點轉換、封裝廠變更、測試機台汰換等事件，皆應觸發該測項的重新驗證，不可視為一次性決策（測試平台遷移的注意事項見 §13.5）。 Periodic re-validation: process node changes, assembly house changes, tester replacement, and similar events should all trigger re-validation of the item — this is never a one-time decision (see §13.5 for tester-platform migrations).

8.1 Bin-level 觸發界限（SYL／SBL）— 及早攔截高 loss 的事故 lot8.1 Bin-Level Trigger Limits (SYL / SBL) — Catching High-Loss Incident Lots Early

測項移除或抽測後，剩下的 bin 統計就是最早的警報器。事故 lot（excursion lot）是 loss 與 escape 最集中的地方：越早在第一片、第一個 lot 攔下來，越能減少浪費的測試時間、封裝成本，以及流到客戶端的風險。做法是對 yield 與每個重要 bin 設定統計界限（概念同 AEC-Q002 的 Statistical Yield Limit／Statistical Bin Limit），超出就觸發對應動作。 Once a test is removed or sampled, the remaining bin statistics are the earliest alarm. Incident (excursion) lots are where loss and escapes concentrate: the earlier one is stopped — at the first wafer, the first lot — the less test time and packaging cost are wasted and the less reaches the customer. The approach is to set statistical limits on yield and on each important bin (the same concept as AEC-Q002's Statistical Yield Limit / Statistical Bin Limit) and trigger a defined action when one is exceeded.

界限怎麼算：用歷史 lot 的實際分布，而且要用 robust 統計量——歷史資料裡本來就含有過去的事故 lot，用 classical σ 會把界限撐寬，讓下一次事故躲在界限內（與 §6.2(h) 的 masking effect 相同）： How to compute the limits: use the real distribution of historical lots, with robust statistics — the history already contains past incident lots, and classical σ would widen the limits enough for the next incident to hide inside them (the same masking effect as §6.2(h)):

統計 Bin／Yield 界限Statistical bin / yield limits
\[ \text{SBL}_b = \operatorname{median}(\text{bin}\%_b) + k\,\hat{\sigma}_{\text{robust}}(\text{bin}\%_b) \qquad \text{SYL} = \operatorname{median}(Y) - k\,\hat{\sigma}_{\text{robust}}(Y) \]
\(\hat{\sigma}_{\text{robust}}\) 取的是 lot 與 lot 之間的變異，不是單一 lot 內的二項分布變異。k 常見做法是警告級 3、Hold 級 4（示範值，應依產品歷史誤報率與 loss 成本訂定）。歷史資料量建議至少涵蓋數十個 lot，並定期（如每季）重算。 \(\hat{\sigma}_{\text{robust}}\) is the lot-to-lot variation, not the binomial variation within a single lot. A common choice is k = 3 for warning and 4 for hold (illustrative — set them from the product's historical false-alarm rate and loss cost). The history should cover at least a few dozen lots and be recomputed periodically (e.g., quarterly).
不要直接用二項分布（p-chart）算界限Don't Compute the Limits Straight from the Binomial (p-chart)

示範：某 bin 平均 0.5%，每 lot 50,000 顆。二項分布的 3σ 只有 \(3\sqrt{0.005 \times 0.995 / 50000} \approx 0.095\%\)，界限 ≈ 0.595%；但實際 lot 與 lot 之間的 robust σ 可能是 0.15%，經驗界限 ≈ 0.5% + 3 × 0.15% = 0.95%。用二項界限的話，大量正常 lot 都會被判超標，警報很快就沒人理會——lot 間變異遠大於二項分布假設（overdispersion）。極少出現的 killer bin（如 open-short、ESD 類）則改用次數界限：假設平均每 lot 2 顆（Poisson λ = 2），一個 lot 出現 ≥ 9 顆的機率只有約 0.02%，可設為 Hold 門檻（示範數字）。 Illustration: a bin averaging 0.5%, 50,000 die per lot. The binomial 3σ is only \(3\sqrt{0.005 \times 0.995 / 50000} \approx 0.095\%\), giving a limit ≈ 0.595%; but the real lot-to-lot robust σ might be 0.15%, giving an empirical limit ≈ 0.5% + 3 × 0.15% = 0.95%. With the binomial limit, many normal lots would trip it and the alarm would soon be ignored — lot-to-lot variation far exceeds the binomial assumption (overdispersion). For rare killer bins (e.g., open-short or ESD-type), use a count limit instead: if a lot averages 2 such die (Poisson λ = 2), the chance of ≥ 9 in one lot is only about 0.02%, which makes a reasonable hold threshold (illustrative numbers).

事故 lot 的處置： Handling an incident lot:

  1. Hold 並交 MRB：由 Material Review Board 判定——加測、加嚴 PAT／NNR 篩選後放行、報廢，或通知客戶後放行。 Hold and send to MRB: the Material Review Board decides — extra testing, release after tightened PAT/NNR screening, scrap, or release with customer notification.
  2. 恢復完整覆蓋：該 lot 所有已移除／抽測的測項恢復 100% 測試，§11 的 adaptive flow 也關閉（見下方紅框）。 Restore full coverage: every removed/sampled item goes back to 100% testing for that lot, and §11's adaptive flow is switched off (see the red box below).
  3. 擴大圍堵到 sister lot：查出同一時段經過同一機台、同一批材料的其他 lot，在它們進入測試或出貨前先套用同樣的檢查——事故往往不只一個 lot。 Extend containment to sister lots: find other lots that went through the same tool, period, or material batch, and apply the same checks before they're tested or shipped — an incident rarely affects only one lot.
  4. 回寫 Phase 3：把事故 lot 上恢復測試的結果另外統計 Incremental Catch。冗餘性只在正常 lot 上被證明過是不夠的；若事故 lot 上出現了被移除測項的 Incremental Catch，該測項的 TTR 決策要重新評估。 Feed back into Phase 3: count Incremental Catch separately on the restored tests of incident lots. Redundancy proven only on normal lots isn't enough; if a removed item shows Incremental Catch on an incident lot, its TTR decision must be re-evaluated.
事故 lot 一律恢復完整測試Incident Lots Always Get the Full Test Back

TTR 的統計證據是在「製程正常」的條件下建立的：相關性、margin、分區良率都假設製程在基準範圍內。事故 lot 正好打破這個前提——製程異常時，兩站的相關性可能崩掉，平常冗餘的測項可能突然變成唯一抓得到問題的那一個。因此觸發 Hold 的 lot，不論 Phase 3 的證據多強，都必須恢復所有已移除／抽測的測項並關閉 adaptive flow，直到 MRB 結案。 TTR's statistical evidence was built under a normal process: correlations, margins, and zonal yields all assume the process is within its baseline. An incident lot breaks exactly that assumption — under a process excursion, cross-stage correlation can collapse, and a normally redundant item can suddenly become the only one that catches the problem. So any lot that triggers a hold must have every removed/sampled item restored and the adaptive flow switched off until the MRB closes it, no matter how strong the Phase 3 evidence is.

10Phase 7（Optional）— 客訴快速查證與覆蓋回補Phase 7 (Optional) — Customer Complaint Quick Verification & Coverage Recovery

這個 Phase 是事件觸發，不是循序執行的步驟，所以不畫在 Section 2 的七階段管線圖裡 —— 它是 Phase 6 回退觸發條件中「客戶端出現對應 fail mode」這一項的具體操作程序，目標是縮短「客訴發生」到「查明是否誤移除、並恢復覆蓋」之間的時間。若組織尚未有正式的客訴（CQC）流程可對接，此 Phase 可暫不導入，故標示為 Optional。 This phase is event-triggered, not a sequential step, so it isn't drawn into Section 2's seven-phase pipeline — it's the concrete operating procedure behind Phase 6's rollback trigger "the corresponding fail mode appears in the field," aimed at shrinking the time between a complaint landing and confirming whether a test was wrongly removed and restoring coverage. If the organization has no formal CQC process to plug into yet, this phase can be deferred — hence marked Optional.

  1. CQC 進線：從客訴中萃取出對應的 fail mode／電性參數／bin。 CQC intake: extract the associated fail mode / electrical parameter / bin from the complaint.
  2. 比對決策紀錄：用該參數查詢 §13.2 的決策紀錄（Risk & Decision Log）—— 這個測項目前是「保留」「抽測」還是「已移除」？ Cross-check the decision log: look up that parameter in the §13.2 Risk & Decision Log — is this test item currently "kept," "sampled," or "removed"?
  3. 若為已移除或抽測 → 立即觸發 Phase 6 的回退條件，恢復 100% 測試，不等待正式審核流程；根因調查與統計覆核可以並行進行，不應拖延恢復覆蓋的時間。 If removed or sampled → immediately trigger the Phase 6 rollback, restoring 100% testing without waiting for a formal review cycle; root-cause investigation and statistical re-validation can run in parallel and should not delay restoring coverage.
  4. 若查無對應測項（真正的覆蓋缺口）→ 這比「移除錯誤」更嚴重，代表整個流程從未涵蓋這個 fail mode。依缺口類型不同，處置方向也不同，不是每次都只是「加一個測項」這麼簡單： If no corresponding test item exists at all (a genuine coverage gap) → this is more serious than a wrong removal — it means the flow never covered this fail mode. The right response depends on what kind of gap it is; it isn't always as simple as "add one test":
    • 數位邏輯 fault coverage 不足（如 stuck-at、delay／transition fault 沒被涵蓋）→ 問題出在比本 SOP 更底層的地方：測試向量／ATPG 產生時的 fault model 本身就沒涵蓋到。不能只在既有測項裡找哪個被拿掉，必須退回最原始的 fault coverage review，重新評估 fault model 與向量集合是否足夠——這已經超出「跨站冗餘」的範疇。這正是 Phase 0 §3.5 本該主動查證、卻沒查到的缺口，事後也要回頭檢討 §3.5 的查證程序哪裡漏了。 Insufficient digital-logic fault coverage (e.g., stuck-at or delay/transition faults never covered) → the problem sits below this SOP's layer entirely: the fault model used to generate test vectors/ATPG never covered it. Don't just look for which existing item was removed — go back to a from-scratch fault-coverage review of the fault model and vector set; this is outside the scope of "cross-stage redundancy." This is exactly the gap Phase 0 §3.5 was supposed to catch proactively and didn't — afterward, also review where §3.5's verification procedure fell short.
    • 原始測試內容的應力（stress）不足，無法激發 latent defect（如電壓／溫度／頻率範圍不夠）→ 這不是「被移除」的覆蓋，而是「原本就不夠強」的覆蓋，出貨後在客戶端長期使用的應力下才被激發。處置方向是加嚴或新增應力條件（如提高電壓 guardband、延長 burn-in），而不是恢復某個被移除的測項。同樣屬於 Phase 0 §3.5 應力條件查證本該攔下的缺口，也要一併檢討查證程序。 Insufficient stress in the original test content to excite a latent defect (e.g., too narrow a voltage/temperature/frequency range) → this isn't coverage that was removed, it's coverage that was never strong enough to begin with, only excited later under the customer's real-world usage stress. The fix is tightening or adding stress conditions (e.g., a wider voltage guardband, longer burn-in), not restoring some removed item. This also falls under what Phase 0 §3.5's stress-condition verification was supposed to catch — review that verification procedure too.
    • Assembly／封裝後造成的客訴（如 bump crack、die crack 等機械性裂紋）→ 雖然發生在 electrical coverage flow 的末端、甚至在電性測試範圍之外，做 TTR 決策時仍需一併考慮：某些電性測項雖然主要目的不是測封裝，卻可能間接捕捉到封裝異常造成的電性徵狀（如接合不良造成的漏電流異常）——若只因統計上看起來冗餘就移除，等於也拿掉了這層間接防護。這類機械性裂紋往往要等可靠度應力（temperature cycling、drop test…）或現場長期使用才會顯現，一旦客訴牽涉到這類缺陷，通常代表需要重新啟動封裝可靠度驗證（reliability requalification），根因需要跟封裝／組裝工程協同調查，不是單靠電性測試資料能完全定位的。 Assembly/package-related complaints (e.g., mechanical cracks such as bump cracks or die cracks) → these occur at the tail end of the electrical coverage flow, or even outside it entirely, but still need to be weighed during TTR: some electrical items, even though not designed to test packaging directly, may indirectly catch an electrical symptom of a package defect (e.g., abnormal leakage from a bad bond). Removing such an item just because it looks statistically redundant also removes that indirect protection. These mechanical cracks often only surface under reliability stress (temperature cycling, drop test…) or after long-term field use; a complaint involving this class of defect usually means package reliability requalification needs to restart, and root cause needs joint investigation with packaging/assembly engineering — electrical test data alone can't fully localize it.
    • 多重因子交互作用下的「unknown unknown」 → TTR 分析本質上是根據「已知」的失效模式與相關性做決策，無法窮舉未來才會出現的多因子交互作用。這類狀況一旦在移除後才浮現，代表當初的風險模型有沒涵蓋到的維度，不能只是簡單恢復測項就結案——必須重新啟動完整分析，必要時走 8D（問題描述、圍堵、根因、矯正措施、預防再發），並把這次事件學到的新失效模式回饋進 Phase 0 的候選篩選準則，避免同類問題在其他產品重演。 Multi-factor "unknown unknown" interactions → TTR analysis is fundamentally a decision based on known failure modes and known correlations; it can't exhaustively anticipate every future multi-factor interaction. If one surfaces after a removal, the original risk model had a dimension it never covered — don't just restore the item and call it done. Re-launch a full analysis, and where warranted run an 8D (problem description, containment, root cause, corrective action, prevent recurrence), feeding the newly learned failure mode back into Phase 0's screening criteria so the same gap doesn't repeat on other products.
    範圍界線：可靠度重新驗證不在本 SOP 範圍內Scope Boundary: Reliability Requalification Is Not Part of This SOP

    Bump crack、die crack 這類機械性根因一旦確認，後續的封裝可靠度重新驗證（測試方法、應力條件、判定準則）屬於封裝可靠度工程的專業範圍，不在本 SOP 討論範圍內。本 SOP 在這類事件中的責任只到：(1) 判斷客訴是否與被移除／降頻的電性測項有關，若有依步驟 3 恢復覆蓋；(2) 一旦判斷根因是封裝／機械性，正式轉交封裝可靠度工程主責，並在決策紀錄中註記轉交對象與時間——不要在本流程內自行展開可靠度分析。 Once a mechanical root cause like a bump crack or die crack is confirmed, the resulting package reliability requalification (test methods, stress conditions, pass/fail criteria) is package reliability engineering's domain, outside this SOP's scope. This SOP's responsibility in such an event stops at: (1) determining whether the complaint relates to a removed/sampled electrical test item — if so, restore coverage per step 3; (2) once the root cause is judged package/mechanical, formally hand off to package reliability engineering, noting who received the handoff and when in the decision log — don't run a reliability analysis within this process itself.

    無論屬於哪一種，都要回頭檢視 Phase 0 §3.2 零覆蓋守則當初是否有漏判，並依 §2 的紅色虛線回饋迴路，讓整個流程從候選測項重新走一次，而不是只在 Phase 6／7 之間打轉。 Whichever category it falls into, revisit whether Phase 0 §3.2's zero-coverage guard missed something, and follow §2's red dashed feedback loop to restart the whole process from the candidate item — don't just cycle between Phase 6 and Phase 7.

  5. 回寫紀錄：把這次 CQC 事件、判定為哪一類缺口、與處置結果補進決策紀錄，作為未來稽核與流程覆核的依據。 Log it back: record the CQC event, which gap category it was classified as, and its resolution in the decision log, as evidence for future audits and process reviews.
目標：查證速度優先於流程完整度Goal: Verification Speed Over Process Completeness

Step 2–3 的目的是在數小時內給出「是否恢復覆蓋」的答案，不是走完整套 Phase 0–6 的重新驗證。正式的根因分析、統計覆核、變更紀錄可以晚一點補齊，但「先恢復覆蓋」不應該被這些流程卡住 —— 這正是 Phase 6 把「客戶端出現對應 fail mode」單獨列為可跳過審核的回退觸發條件的原因。 Steps 2–3 exist to answer "should coverage be restored" within hours, not to re-run the full Phase 0–6 validation. Formal root-cause analysis, statistical re-validation, and change documentation can catch up later, but restoring coverage should never be blocked on them — this is exactly why Phase 6 calls out "the corresponding fail mode appears in the field" as a rollback trigger that skips the approval cycle.

11WT 自適應測試（Adaptive Test）— 依晶圓區域與產品成熟度動態調整WT Adaptive Test — Adjusting Test Content by Wafer Zone & Product Maturity

Phase 4 的「抽測／移除」是對整個母體的靜態決策——同一個測項對每顆 die 一視同仁。Adaptive Test 則是在 WT 依據證據（產品成熟度、晶圓區域良率與 bin Pareto、客訴歷史位置、同 lot 前段 wafer 的結果）對不同 wafer、不同區域的 die 套用不同的測試內容：證據顯示低風險的區域跑精簡 flow 節省 test time 與成本，高風險區域維持全測。核心原則：Adaptive Test 只能把測試從「有證據證明低風險」的 die 身上拿掉，不能把風險平均攤到整片 wafer 上。 Phase 4's "sample/remove" is a static, whole-population decision — every die is treated the same for a given item. Adaptive Test instead uses evidence at WT (product maturity, zonal yield and bin Pareto, the wafer locations of past customer complaints, results from earlier wafers in the same lot) to apply different test content to different wafers and different regions of a wafer: regions the evidence shows are low-risk run a reduced flow to save test time and cost, high-risk regions keep the full flow. Core principle: Adaptive Test may only take tests away from die that evidence shows are low-risk — it must never spread the risk evenly across the whole wafer.

與 Phase 0–7 的關係How This Relates to Phase 0–7

Adaptive Test 不是另一套獨立流程，而是 Phase 4「抽測」決策在 WT 的精細化執行方式。一個測項要進入 adaptive 候選池，必須先通過 Phase 0 硬性守則與 Phase 3 統計證據，並落在 Phase 4 允許抽測的 Tier（B／C）——Tier A 測項不進入 adaptive 候選池。導入時一樣走 Phase 5 pilot、Phase 6 正式變更與回退，客訴時一樣由 Phase 7 查證。Adaptive 規則本身（分區定義、門檻、切換邏輯）就是測試程式的一部分，必須走 Phase 4 的標準 release 流程並納入版本控管。 Adaptive Test isn't a separate process — it's a finer-grained way of executing Phase 4's "sample" decision at WT. To enter the adaptive candidate pool, an item must first pass the Phase 0 hard gates and the Phase 3 statistical evidence, and fall in a Tier that Phase 4 allows to be sampled (B/C) — Tier A items never enter the adaptive pool. Rollout still goes through the Phase 5 pilot and Phase 6 formal change and rollback, and complaints are still verified through Phase 7. The adaptive rule set itself (zone definitions, thresholds, switching logic) is part of the test program and must go through Phase 4's standard release process under version control.

11.2 分區定義 — Radial、邊緣距離、扇區、列／行帶、Shot 位置11.2 Defining Zones — Radial, Edge Distance, Sector, Row/Column Bands, Shot Position

分區方式同時決定「能省多少」與「需要多少樣本」：分區越細，省得越精準，但每區的 die 越少，每區要累積的 lot 就越多（見 §11.6）。原則：用最少的分區，抓住真實、統計上顯著的空間差異，且分區形狀要對應到實際的物理機制。 The zoning scheme sets both how much you can save and how many samples you need: finer zones save more precisely, but each zone holds fewer die and so needs more lots accumulated (see §11.6). Principle: use the fewest zones that capture real, statistically significant spatial differences, and shape them to match an actual physical mechanism.

多 site probe card 下，每個 touchdown 的 site 編號與 die 位置有固定對應；若某個 site 有 contact 或儀器問題，它在 wafer map 上會呈現規則的列／行 pattern，看起來像是空間效應。訂分區前先做 site-to-site 比較（§3.4 量測系統有效性），排除 site 造成的 pattern，也不要定義出跟 site 排列重疊的分區。 With a multi-site probe card, each touchdown's site number maps to die positions in a fixed way; if one site has a contact or instrument problem, it shows up on the wafer map as a regular row/column pattern that looks like a spatial effect. Run a site-to-site comparison (§3.4 measurement-system validity) before defining zones to rule out site-induced patterns, and never define a zone that overlaps the site layout.

11.3 Zonal Yield 與 Bin Pareto — 找出「哪裡可以省」11.3 Zonal Yield & Bin Pareto — Finding Where to Save

  • 分區先定好：依 §11.2 定義並凍結分區後才做以下統計；看完資料再「畫」出最好看的分區，等於在雜訊裡找規律（overfitting）。 Zones come first: define and freeze the zones per §11.2 before running the statistics below; drawing the best-looking zones after seeing the data is finding patterns in noise (overfitting).
  • 逐區、逐測項統計：每個分區分別計算 zonal yield、各測項的 fail rate，以及該測項的 incremental catch（只有它抓到、其他測項都沒抓到的 fail）。典型結果是邊緣區 fail rate 較高、Pareto 也不同（膜厚、蝕刻、微影的邊緣效應），中心區則乾淨得多——這正是分區省時的空間。 Statistics per zone, per item: for each zone separately, compute zonal yield, each item's fail rate, and its incremental catch (fails only that item caught). The typical result is a higher fail rate and a different Pareto at the edge (film thickness, etch, and litho edge effects), with a much cleaner center — that difference is exactly where zonal savings come from.
  • Bin Pareto 判讀：在某分區佔 fail 大宗（如累計前 80%）的 bin 對應測項，就是該區的主要攔截者，維持全測；在該區 incremental catch 為零、且樣本數足夠的測項，才是該區的 skip 候選。樣本數要逐區計算（§6.1 的 zero-failure 公式套用在單一分區的 die 數上），不能用整片 wafer 的總數——小分區通常要累積更多 lot 才夠；完整的樣本數設計見 §11.6。 Reading the bin Pareto: items behind the bins that make up most of a zone's fails (e.g., the top 80% cumulative) are that zone's main catchers — keep them on full test. Only items with zero incremental catch in that zone, backed by enough samples, are skip candidates there. Compute the sample size per zone (apply §6.1's zero-failure formula to that zone's die count alone), not from the whole-wafer total — small zones usually need more lots accumulated. See §11.6 for the full sample-size design.
Pareto 排名低 ≠ 不重要；stop-on-fail 會讓 Pareto 失真Low Pareto Rank ≠ Unimportant; Stop-on-Fail Distorts the Pareto

Pareto 衡量的是「頻率」，不是「嚴重度」：一個很少 fail 的測項，可能是某個罕見但致命失效模式的唯一攔截者，排名低不代表可以省——一律要對照 FMEA 的 Severity 與 Phase 0 §3.2 零覆蓋守則。另外，若基準資料是 stop-on-fail 收的，排在 flow 後段的測項會因為 die 已在前面 fail 而沒被執行，fail 數被系統性低估；分區 Pareto 的基準資料應以 continue-on-fail 收集（這也是 NPI 階段要求 continue-on-fail 的原因）。 A Pareto measures frequency, not severity: an item that rarely fails may be the only catcher of a rare but critical failure mode, so a low rank doesn't make it skippable — always check FMEA Severity and the Phase 0 §3.2 zero-coverage guard. Also, if the baseline data was collected stop-on-fail, items late in the flow never ran on die that had already failed earlier, so their fail counts are systematically understated; zonal Pareto baselines should be collected continue-on-fail (which is why the NPI stage requires it).

11.4 CQC 位置 — 鎖定不可省的區域11.4 CQC Locations — Locking the Zones You Can't Skip

  • 回推晶圓座標：用 §5 的 die-level 追溯，把每一顆 CQC／RMA 退貨 die 回推到 Wafer ID + X,Y，疊成一張累積客訴 wafer map（stacked map）。 Trace back to wafer coordinates: use §5's die-level traceability to map every CQC/RMA return die back to Wafer ID + X,Y, and stack them into a cumulative complaint wafer map.
  • 鎖定區（locked zone）：客訴 die 落點所在的分區，連同周圍一圈緩衝 die（如 ±1–2 顆），對與該客訴相關的測項設為永久全測，不論分區統計多乾淨。若客訴 die 無法追溯到座標，則該相關測項整片 wafer 都不做分區 skip。 Locked zones: the zone where complaint die landed, plus a buffer ring of surrounding die (e.g., ±1–2 die), is set to permanent full test for the items related to that complaint, no matter how clean the zonal statistics look. If a complaint die can't be traced to coordinates, the related items get no zonal skipping anywhere on the wafer.
  • 反過來檢查分區定義：客訴 die 若呈現空間聚集，代表有一個空間性的失效機制；應回頭檢討 §11.2 的分區定義是否把這個機制切到了「精簡」那一邊。 Check the zone definition in reverse: if complaint die cluster spatially, there is a spatial failure mechanism — revisit whether §11.2's zone definition put that mechanism on the "reduced" side.
CQC 鎖定區不可被統計結果解鎖CQC-Locked Zones Can't Be Unlocked by Statistics

客戶已經從某個區域收到過不良品，就代表這個區域的實際風險已被現場證實；之後再多乾淨的分區資料都不能自動解鎖。唯一的解鎖路徑是：對應的 8D 已結案、矯正措施已驗證有效，並重新走一次 Phase 4 的設計端 review 與簽核。 Once a customer has received a defective unit from a zone, that zone's real-world risk has been confirmed in the field; no amount of clean zonal data afterward can unlock it automatically. The only unlock path is a closed 8D with a verified-effective corrective action, followed by a fresh Phase 4 designer review and sign-off.

11.5 WT 執行機制 — 在 tester 上怎麼做11.5 Execution at WT — How It Runs on the Tester

  1. Sentinel wafer：每個 lot 指定幾片 wafer（如第 1 片，加上 lot 中段與末段各 1 片）跑完整 flow（continue-on-fail），結果與產品基準比對：zonal yield、bin Pareto、主要參數 mean／σ、PAT outlier 數。全部在基準範圍內 → 其餘 wafer 才可使用 adaptive flow；任一超出 → 整個 lot 全測。 Sentinel wafers: designate a few wafers per lot (e.g., the first, plus one mid-lot and one at the end) to run the full flow (continue-on-fail), and compare their results against the product baseline: zonal yield, bin Pareto, key-parameter mean/σ, PAT outlier count. All within baseline → the remaining wafers may use the adaptive flow; any outside → the whole lot runs full test.
  2. Feed-forward：若有 PCM／WAT 資料，lot 的 WAT 參數超出基準窗口時直接全測，不必等 sentinel wafer 結果。 Feed-forward: where PCM/WAT data is available, a lot whose WAT parameters fall outside the baseline window goes straight to full test without waiting for the sentinel wafer results.
  3. 分區指派 flow：符合條件的 wafer 上，中心／中間區跑精簡 flow；邊緣區與 CQC 鎖定區跑完整 flow。 Assign flows by zone: on eligible wafers, the center/middle zones run the reduced flow; the edge zone and CQC-locked zones run the full flow.
  4. Monitor die：每個精簡區每片 wafer 保留一組 die 跑完整 flow（固定位置加上隨機位置，隨機是為了避免系統性盲點），提供被 skip 測項的連續 parametric 資料給 SPC——少了它們，就看不到正是被省掉的那些測項有沒有在漂移。 Monitor die: in every reduced zone on every wafer, keep a set of die on the full flow (fixed positions plus random ones — the random positions prevent systematic blind spots). They supply continuous parametric data on the skipped items to SPC; without them, there's no way to see whether the very items you're skipping are drifting.
  5. 鄰近 die 升級：依探針順序已測過的鄰近 die 若有 fail（Good-Die-in-Bad-Neighborhood，見 §6.2(f) NNR），這顆 die 自動升級為完整 flow——精簡 flow 只跑在鄰居乾淨的地方。 Neighborhood upgrade: if an already-probed neighboring die failed (Good Die in Bad Neighborhood — see §6.2(f) NNR), this die is automatically upgraded to the full flow; the reduced flow only runs where the neighborhood is clean.
  6. 即時切回全測：以下任一發生，該 wafer 剩餘部分（嚴重時整個 lot）自動切回完整 flow 並記錄原因：monitor die 在被 skip 的測項上 fail、zonal yield 低於基準下限、連續 fail 或 contact 異常、更換 probe card／tester、PAT outlier 數超標；lot 觸發 §8.1 的 Hold 時，整個 lot 一律跑完整 flow。 Real-time switch back to full test: if any of these occur, the rest of the wafer (or the whole lot, if serious) automatically reverts to the full flow and the reason is logged: a monitor die fails a skipped item, zonal yield drops below the baseline lower limit, consecutive fails or contact anomalies, a probe-card/tester change, or the PAT outlier count exceeds its limit. A lot that triggers an §8.1 hold runs entirely on the full flow.

11.7 品質守則 — 省時間但不犧牲品質11.7 Quality Safeguards — Saving Time Without Sacrificing Quality

零覆蓋守則以「每顆 die」為單位The Zero-Coverage Guard Applies Per Die

Phase 0 §3.2 的零覆蓋守則在 adaptive 情境下要以每顆 die 檢查，不是以母體檢查：一顆跑精簡 flow 的 die，被 skip 的失效模式必須仍在其他地方被覆蓋（如 FT 的同一或高相關測項）。若被 skip 的 WT 測項是該失效模式在整個流程中的唯一覆蓋，就不能進入 adaptive 候選池——「大部分 die 都有測到」不能抵銷「這幾顆 die 完全沒測到」。 In an adaptive setting, Phase 0 §3.2's zero-coverage guard must be checked per die, not per population: for a die on the reduced flow, every failure mode it skips must still be covered somewhere else (e.g., the same or a highly correlated item at FT). If the skipped WT item is that failure mode's only coverage anywhere in the flow, it can't enter the adaptive pool — "most die got tested" doesn't offset "these die were never tested at all."

Escape 預算：adaptive 規則核准前，先估算整體 escape DPPM，且必須低於 Phase 4 該 Tier（或客戶）允許的上限；同一套分區參數也直接給出平均每顆 die 節省的 test time，放進 Phase 4 的 ROI 計算： Escape budget: before approving an adaptive rule set, estimate the overall escape DPPM, which must stay below the limit Phase 4 allows for that Tier (or the customer allows); the same zonal parameters also give the average test time saved per die, which goes into the Phase 4 ROI calculation:

Adaptive 預期 escape 與節省時間Adaptive expected escape & time saved
\[ \text{DPPM}_{\text{escape}} \approx 10^{6}\sum_{z} f_z\, s_z\, p_{z,\text{UCL}} \qquad \Delta TT \approx \sum_{z} f_z\, s_z\, t_{\text{skip}} \]
\(f_z\)：分區 z 佔整片 die 的比例；\(s_z\)：分區 z 中跑精簡 flow 的比例（扣掉 monitor die 與鄰近升級）；\(p_{z,\text{UCL}}\)：被 skip 測項在分區 z 的 incremental fail rate 信賴上界（用 Clopper–Pearson，零 fail 時約為 \(3/n_z\)），不是點估計；\(t_{\text{skip}}\)：被 skip 測項的 test time。 \(f_z\): fraction of the wafer's die in zone z; \(s_z\): fraction of zone z running the reduced flow (net of monitor die and neighborhood upgrades); \(p_{z,\text{UCL}}\): the upper confidence bound of the skipped item's incremental fail rate in zone z (Clopper–Pearson; about \(3/n_z\) with zero fails), not the point estimate; \(t_{\text{skip}}\): test time of the skipped items.
  • 先 shadow run 再真正 skip：Phase 5 pilot 的第一步建議是「影子模式」——照常跑完整 flow，但讓 adaptive 規則在背景算出「本來會 skip 哪些 die」，再比對那些 die 在被 skip 測項上的實際結果。影子期間零漏抓，才切換成真的 skip。 Shadow-run before skipping for real: the recommended first step of the Phase 5 pilot is shadow mode — keep running the full flow, but let the adaptive rules compute in the background which die they would have skipped, then compare against those die's actual results on the skipped items. Switch to real skipping only after zero misses in the shadow period.
  • 定期全 lot 重建基準：每 N 個 lot 安排一個整 lot 完整 flow，重新計算 zonal yield 與 Pareto，避免基準隨製程緩慢漂移而失真。 Re-baseline with periodic full lots: schedule one whole lot on the full flow every N lots to recompute zonal yield and Pareto, so the baseline doesn't go stale as the process slowly drifts.
  • 客戶同意：許多車用與高可靠度客戶把 adaptive flow 視為測試流程變更，需事先通知或核准（PCN）；pilot 前先確認客戶協議。 Customer agreement: many automotive and high-reliability customers treat an adaptive flow as a test-flow change requiring advance notice or approval (PCN); confirm the customer agreement before the pilot.

12片上量測（On-Chip Measurement）取代外部儀器On-Chip Measurement in Place of External Instruments

另一條 TTR 路線不是「移除測項」，而是「換量測方法」：讓晶片用自己的 ADC、感測器或 BIST 量測內部訊號，再透過 scan／JTAG 以數位碼回傳，測試機只負責讀碼，不再用 PMU、DPS、digitizer 等外部儀器逐一量測。測項還在，但量測時間大幅縮短。 Another TTR route isn't removing a test but changing how it's measured: the chip measures internal signals with its own ADC, sensors, or BIST and reports digital codes over scan/JTAG, so the tester only reads codes instead of measuring each signal with external instruments such as a PMU, DPS, or digitizer. The test item stays; its measurement time shrinks dramatically.

與 Phase 0–7 的關係How This Relates to Phase 0–7

換量測方法就是換量測系統，所以 Phase 0 §3.4（量測系統有效性）是起點；Phase 3 的比較對象不再是「WT vs FT」，而是「片上量測 vs 外部儀器」在同一顆 die 上的一致性；之後同樣走 Phase 4 簽核（設計端 review 特別重要——只有設計端清楚片上電路看得到哪些缺陷、看不到哪些）、Phase 5 pilot 與 Phase 6 回退。 Changing the measurement method means changing the measurement system, so Phase 0 §3.4 (measurement-system validity) is the starting point. In Phase 3 the comparison is no longer "WT vs. FT" but on-chip vs. external-instrument agreement on the same die. After that, the usual Phase 4 sign-off (designer review matters especially here — only the designers know which defects the on-chip circuits can and can't see), Phase 5 pilot, and Phase 6 rollback apply.

12.2 為什麼能省時間12.2 Where the Time Savings Come From

  • 平行化：所有 site、多個量測點可同時進行，不必排隊使用共用儀器（§13.5 的序列化資源問題直接消失）。 Parallelism: all sites and many measurement points run at once instead of queuing for shared instruments (§13.5's serialized-resource problem simply disappears).
  • 沒有切換與穩定等待：不必切 relay、設定儀器量程、等待 settling。 No switching or settling: no relay switching, no instrument range setup, no settling waits.
  • 需要的測試機資源更少：可以提高 site 數，甚至改用較低成本的測試機。 Fewer tester resources: allows a higher site count, or even a lower-cost tester.

示範（虛構數字）：16 site、每顆 8 個內部電源，若共用 PMU 只能逐 site 逐點量測、每點 2 ms，一個 touchdown 要 8 × 16 × 2 = 256 ms；改由片上 ADC 一次讀出所有電源、所有 site 平行經 scan 回傳，可能只需約 10 ms。 Illustration (made-up numbers): 16 sites, 8 internal rails per die. If a shared PMU can only measure site by site, point by point, at 2 ms each, one touchdown takes 8 × 16 × 2 = 256 ms; with an on-chip ADC reading all rails at once and all sites reporting in parallel over scan, it might take about 10 ms.

12.3 最大的風險：晶片在量自己12.3 The Biggest Risk: The Chip Is Measuring Itself

外部儀器有自己獨立、經過校正的參考；片上量測的「尺規」卻是晶片自己的電路。當缺陷同時影響受測電路與量測電路的共用參考時，兩者一起偏移，讀值看起來完全正常——這是片上量測特有、外部儀器不會發生的失效模式（common-mode failure）。 An external instrument has its own independent, calibrated reference; an on-chip measurement's "ruler" is the chip's own circuitry. When a defect affects a reference shared by the circuit under test and the measuring circuit, both shift together and the reading looks perfectly normal — a common-mode failure unique to on-chip measurement that an external instrument can't suffer.

保留至少一個外部「錨點量測」Keep at Least One External Anchor Measurement

片上量測不能成為它所依賴之參考的唯一檢查。每顆 die 至少保留一個以外部儀器量測的絕對錨點——例如直接量 bandgap 或 ADC 參考電壓，或由測試機強制一個已知電壓讓片上 ADC 讀取、比對讀值是否正確。少了這個錨點，整組片上量測可能一起偏移而沒有任何機制發現，無論相關性統計多漂亮都一樣。 An on-chip measurement must never be the only check of the reference it depends on. Keep at least one absolute anchor measured with an external instrument on every die — for example, measure the bandgap or ADC reference directly, or have the tester force a known voltage for the on-chip ADC to read and check that the code is right. Without that anchor, the whole set of on-chip measurements can drift together with nothing to catch it, no matter how good the correlation statistics look.

其他風險： Other risks:

  • 規格定義在 pin 上：若 datasheet 或客戶規格把參數定義為「在 pin 上、以指定條件量測」，片上的內部量測不能直接取代，屬於 Phase 0 §3.1 的規格強制範圍，需客戶同意。 Specs defined at the pin: if the datasheet or customer spec defines a parameter as "measured at the pin under stated conditions," an internal on-chip reading can't substitute directly — it falls under Phase 0 §3.1's spec-mandated scope and needs customer agreement.
  • 看不到 pin 層級缺陷：pad open、pin 漏電、ESD 損傷、封裝與外部走線問題，片上電路都看不到——移除對應的外部量測前要先過 Phase 0 §3.2 零覆蓋守則。 Blind to pin-level defects: pad opens, pin leakage, ESD damage, and package or external-path problems are invisible to on-chip circuits — pass the Phase 0 §3.2 zero-coverage guard before dropping the matching external measurement.
  • 精度與解析度：ADC 的 LSB、INL／DNL、雜訊與溫度漂移都會進入量測不確定度，必須小於 spec 容許範圍的一小部分（見 §12.4 的 guardband）。 Accuracy and resolution: the ADC's LSB, INL/DNL, noise, and temperature drift all feed the measurement uncertainty, which must be a small fraction of the spec tolerance (see §12.4's guardband).
  • 相依性：片上量測電路要先能正常上電、運作（常還要先 trim）；前段 fail 的 die 可能根本讀不到值，與 stop-on-fail 的資料缺口一樣要分開處理（§5.3）。 Dependencies: the on-chip measurement circuitry must power up and work first (often after trim); die that failed earlier may return no reading at all — handle that gap separately, like stop-on-fail missing data (§5.3).

12.4 導入驗證步驟12.4 Validation Steps for Adoption

  1. Phase 0 篩選：確認是否為規格強制的 pin 層級參數（§3.1）、改用片上量測後是否造成任何失效模式零覆蓋（§3.2）；由設計端列出片上電路看得到與看不到的缺陷。 Phase 0 screening: check whether the parameter is spec-mandated at the pin (§3.1) and whether switching to on-chip leaves any failure mode with zero coverage (§3.2); have the designers list which defects the on-chip circuit can and can't see.
  2. 方法比對（method comparison）：同一批 die 用兩種方法都量（外部儀器為參考），涵蓋多個 lot、溫度 corner 與 site。只看相關係數 r 不夠——r 高只代表兩者一起變動，不代表數值一致；要看偏差（bias）、一致性界限（limits of agreement）、整個量測範圍內的線性，以及片上方法本身的重複性（Gauge R&R）。 Method comparison: measure the same die both ways (external instrument as the reference), across several lots, temperature corners, and sites. The correlation r alone isn't enough — a high r only means the two move together, not that they agree; examine the bias, the limits of agreement, linearity across the full range, and the on-chip method's own repeatability (Gauge R&R).
    Bland–Altman 一致性界限Bland–Altman limits of agreement
    \[ d_i = x_{\text{on-chip},i} - x_{\text{ext},i}, \qquad \text{LoA} = \bar{d} \pm 1.96\, s_d \]
  3. 依不確定度設 guardband：先校正系統性偏差，再把片上量測的不確定度 u 從 spec limit 往內收（概念同 §6.2(g) 與 ILAC-G8 的判定規則）： Guardband for uncertainty: correct the systematic bias first, then pull the test limits in from the spec limits by the on-chip measurement uncertainty u (the same idea as §6.2(g) and ILAC-G8 decision rules):
    片上量測的測試 limitTest limits for an on-chip measurement
    \[ \text{TL}_{\text{upper}} = \text{USL} - k\,u, \qquad \text{TL}_{\text{lower}} = \text{LSL} + k\,u \]
    k 依目標信心選擇（常用 k = 2）。收得越多，良率損失越大；若 k·u 吃掉 spec 容許範圍的一大塊，代表片上量測不夠準，不適合取代外部量測。 Choose k for the target confidence (k = 2 is common). The more you pull in, the more yield you lose; if k·u eats a large share of the spec tolerance, the on-chip measurement isn't accurate enough to replace the external one.
  4. 保留錨點量測（§12.3 紅框）。 Keep the anchor measurement (§12.3, red box).
  5. 平行試行：Phase 5 pilot 期間兩種方法同時跑，比對每顆 die 的 pass／fail 判定；特別統計「外部判 fail、片上判 pass」的顆數——這就是片上量測的 Incremental Catch 缺口，處理方式同 §6.1。 Parallel run: during the Phase 5 pilot, run both methods and compare each die's pass/fail call; count especially "external fails, on-chip passes" — that's the on-chip method's Incremental Catch gap, handled as in §6.1.
  6. 持續稽核：導入後定期抽樣以外部儀器量測（如每 lot 幾顆 monitor die），對兩者的差值做 SPC；設計改版、trim 方法變更、測試機更換時重新驗證。 Ongoing audit: after rollout, periodically sample with the external instrument (e.g., a few monitor die per lot) and run SPC on the difference between the two; re-validate after a design revision, a trim-method change, or a tester change.

示範（虛構數字）：某 LDO 輸出規格 1.200 V ± 3%（± 36 mV），片上 ADC LSB = 2 mV。300 顆 die 兩種方法比對：平均差 \(\bar{d} = +4\) mV、差值標準差 \(s_d = 3\) mV → LoA = +4 ± 5.9 mV（−1.9 至 +9.9 mV）。先扣除 +4 mV 的系統偏差，再以 u = 3 mV、k = 2 收 6 mV，片上量測的測試 limit 變為 1.200 V ± 30 mV。下一步是確認這 6 mV 造成的良率損失可以接受（同 §6.2(g) 的 ROI 天平）。 Illustration (made-up numbers): an LDO output spec of 1.200 V ± 3% (± 36 mV), on-chip ADC LSB = 2 mV. Comparing both methods on 300 die: mean difference \(\bar{d} = +4\) mV, standard deviation of the differences \(s_d = 3\) mV → LoA = +4 ± 5.9 mV (−1.9 to +9.9 mV). Correct the +4 mV systematic bias first, then pull in by 6 mV with u = 3 mV and k = 2: the on-chip test limits become 1.200 V ± 30 mV. Next, confirm that the yield lost to those 6 mV is acceptable (the same ROI balance as §6.2(g)).

  • 多 site 與序列化資源：測試時間由整個 touchdown 決定。若某些量測必須逐 site 序列執行（共用儀器、逐 site 迴圈），這類測項的時間會乘上 site 數，是 TTR 最有價值的目標；完全平行執行的測項，移除後省下的可能只有一小段。 Multi-site and serialized resources: test time is set by the whole touchdown. Measurements that must run site by site (shared instruments, per-site loops) cost their time multiplied by the site count, making them TTR's most valuable targets; a fully parallel item may save very little when removed.
  • Datalog 設定決定 STDF 內容：datalog 可設定只記 fail、或記錄所有 parametric 值，以及是否記錄 MPR／FTR 細節。TTR 的基準資料需要完整的 parametric datalog，但 datalog 本身也會增加 test time——量產可用精簡設定，基準 lot 與 pilot lot 要開完整 datalog，並在決策紀錄中註明。 Datalog settings define what's in the STDF: the datalog can record fails only or every parametric value, with or without MPR/FTR detail. TTR baselines need the full parametric datalog, but datalogging itself adds test time — production can use a lean setting while baseline and pilot lots run the full datalog, noted in the decision log.
  • 用 flow 控制實作 skip／adaptive：以 flow 變數與條件分支實作 1-in-N 抽測或依分區查表決定 flow。變數狀態一定要寫進 datalog（如 DTR 文字或 PRR 的 part text），否則 Phase 7 無法回答「這顆 die 跑的是哪個 flow」（§11.5 第 7 點）。 Implement skip/adaptive with flow control: use flow variables and conditional branches for 1-in-N sampling or a zone lookup that picks the flow. Always write the variable state into the datalog (e.g., DTR text or the PRR part text), or Phase 7 can't answer "which flow did this die run?" (§11.5 item 7).
  • Limit 集中管理：§6.2(g) 收緊 limit、§6.2(f) PAT limit 都是測試程式變更，要走 Phase 4 release。Limit 集中在表格（如 test table）而不是寫死在 test method 裡，審查、比對與回退都容易得多。 Centralize limits: §6.2(g) tightened limits and §6.2(f) PAT limits are test-program changes that go through the Phase 4 release. Keeping limits in a table (e.g., a test table) rather than hard-coded in test methods makes review, comparison, and rollback much easier.
平台遷移 = 新程式 + 新量測系統A Platform Migration = New Program + New Measurement System

ST7 → ST8 遷移、測試機世代或儀器板卡更換，TEST_NUM、測項名稱、量測方法、平均次數、settling time 都可能改變。遷移前的 TTR 證據不能直接沿用：遷移前後要用同一批 die 在新舊程式上做 correlation，重新確認 §3.4 量測系統有效性，並觸發 Phase 5 的重新驗證。這也是 §5.3「TEST_NUM 不是跨程式鍵值」最常發生的情境——WT／FT 資料若橫跨遷移前後，必須靠 Phase 1 的測試對應矩陣重新對應。 With an ST7 → ST8 migration, or a tester-generation or instrument-card change, TEST_NUM, test names, measurement methods, averaging counts, and settling times can all change. TTR evidence from before the migration can't carry over directly: run a correlation on the same die across the old and new programs, re-confirm §3.4 measurement-system validity, and trigger Phase 5 re-validation. This is also the most common case of §5.3's "TEST_NUM isn't a cross-program key" — WT/FT data spanning a migration must be re-mapped through the Phase 1 test mapping table.
